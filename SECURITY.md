# Security

## Reporting a vulnerability

Vulnerabilities must not be reported as public issues. Report them through **Security → Report a vulnerability** (private advisory) on GitHub.

## Threat model and mitigations

| Risk | Mitigation | Where |
|---|---|---|
| API key leakage | The key is sent only in an HTTP header. It is never written to URLs, logs or the raw data manifest. The `Secret` object is not exposed through repr/str/pickle. If the server echoes the key back in a response, it is masked in the error message. EPİAŞ: the username and password are sent only in the form body of the ticket request, and the TGT only in the `TGT` header; the TGT is cached in memory (never on disk) under a hash of the credentials, and all three are masked in error messages. | `infrastructure/secret_store.py`, `providers/evds3.py`, `providers/epias.py` |
| Key sent to another server through a modified catalog | Each provider pins its allowed host in code (EVDS3: `evds3.tcmb.gov.tr`, TÜİK: `databrowser2.tuik.gov.tr`, BDDK: `www.bddk.org.tr`, TBB: `verisistemi.tbb.org.tr`, BTK: `www.btk.gov.tr`, EPİAŞ: `seffaflik.epias.com.tr` for data and `giris.epias.com.tr` for the ticket; a catalog `ticket_url` pointing elsewhere is refused; Google Trends: `bigquery.googleapis.com` for queries and `oauth2.googleapis.com` for tokens). The catalog accepts only `https`. The client does not follow redirects and does not use environment proxy settings (`trust_env`). | `providers/evds3.py`, `providers/tbb.py`, `providers/tuik.py`, `providers/bddk.py`, `providers/btk.py`, `providers/epias.py`, `providers/bigquery_trends.py`, `http_client.py`, `catalog_yaml.py` |
| Google credentials (BigQuery) | Credentials come only from Application Default Credentials: the file named by `GOOGLE_APPLICATION_CREDENTIALS` or the gcloud default path (size-capped, `authorized_user` or `service_account` only; other kinds are refused). The refresh token, client secret and private key are held in `Secret` objects and sent only in the form body to the pinned token host `oauth2.googleapis.com` (a key file whose `token_uri` points elsewhere is refused); the access token goes only into the `Authorization` header of `bigquery.googleapis.com`. Tokens are cached in memory (never on disk) and masked in error messages. The google-auth library is not used; service-account JWTs are signed locally with `cryptography`. | `providers/google_auth.py`, `providers/bigquery_rest.py` |
| Query injection and runaway cost (BigQuery) | Only fixed SQL written in the package is sent; terms, dates and the country travel as named query parameters (`parameterMode: NAMED`). Every query filters on the partition column (`refresh_date`) and `country_code = 'TR'`, selects named columns only and carries `maximumBytesBilled` (`BQ_MAX_BYTES_BILLED`, default 5 GiB, accepted range 10 MiB–100 GiB), so BigQuery refuses a larger scan without charging. Queries are billed to the user's own project (`BQ_PROJECT_ID`, validated); raw query responses are not written to bronze. | `providers/bigquery_rest.py`, `providers/bigquery_trends.py` |
| URL parameter injection (EVDS appends parameters to the path without encoding) | Series and data group codes pass an allow-list: `^[A-Za-z0-9][A-Za-z0-9_.]{0,63}$`. | `domain/validation.py` |
| Path traversal | Source and sector identifiers must match `^[a-z0-9_]+$`. Raw file names are derived from the content hash. MCP tools take no file path parameter. | `domain/validation.py`, `storage/*` |
| SQL injection | All values in DuckDB queries are bound as parameters. | `storage/observation_store.py` |
| Untrusted YAML | `yaml.safe_load` is used with a 256 KB size limit, and a strict schema is enforced with pydantic `extra="forbid"`. | `catalog_yaml.py` |
| TLS interception or a weakened trust store | Certificates are always verified (certifi roots, hostname check). Servers that omit their intermediate certificate (TBB `verisistemi.tbb.org.tr`) are served by intermediates shipped in `infrastructure/certs/intermediates.pem` (taken from the certificate's AIA URL, SHA-256 pinned by a test); partial chains are refused, so an intermediate is never a trust anchor and every chain must still end at a certifi root. | `http_client.py`, `infrastructure/certs/` |
| Memory exhaustion (DoS) | Response size limit of 50 MB per source by default; a source that publishes large files may raise it with `max_response_mb` in its catalog entry (BTK: 150 MB), and the catalog refuses values above 200 MB. The limit is checked against `Content-Length` and while the body streams in. Timeouts, rate limiting and a `Retry-After` of at most 120 s are applied. | `http_client.py`, `catalog_yaml.py`, `providers/registry.py` |
| Malformed or hostile PDF files | PDF reports are downloaded only from the provider's pinned host and must start with the `%PDF-` signature. Only the text layer is read with PDFium (pypdfium2); nothing is rendered, executed or written outside the bronze store. | `providers/btk.py` |
| Information leakage through MCP | Expected errors are returned with safe text. The SDK does not send the content of unexpected errors to the client. Tools are marked with read-only/destructive annotations. | `interfaces/mcp_server.py` |
| Local web panel used by other sites (CSRF, DNS rebinding) | The server binds to `127.0.0.1` only. Requests whose Host header is not loopback are rejected. Every `/api` request must carry the random per-launch session token in the `X-MLB-Token` header, and a cross-origin `Origin` is rejected. No CORS. | `interfaces/web/app.py` |
| Script injection (XSS) and information leaks in the web panel | The CSP allows scripts and styles from the same origin only (no `unsafe-inline`) and forbids framing. The frontend writes data with `textContent` only. The API takes and returns no file paths, request bodies are capped at 64 KB while they are read (8 MB for the market share table, which the browser sends as text and the server parses in memory without writing it to disk), and unexpected errors return no details. | `interfaces/web/` |
| Web evidence is untrusted input (published market share figures) | Figures found on the web reach the package only through `record_share_evidence`, which treats every field as hostile: the tier is derived from the domain and never taken from the caller; domains are default-deny with exact or subdomain matching (`rekabet.gov.tr.evil.com` fails); URLs must be https without credentials or a custom port and at most 500 characters; text fields are length-capped, stripped of control characters and refused if they contain an e-mail, phone, national ID or IBAN; a quote is at most 15 words and must contain the recorded figure; targets and forecasts are refused through the period and publication date checks. Page text is never stored, and kap.org.tr keeps a link to one disclosure and no quote. Records live in their own DuckDB file with bound parameters and never reach the observation store or feature panels. | `domain/services/evidence.py`, `catalog_data/evidence_sources.yaml`, `storage/evidence_store.py` |
| Prompt injection through web pages | The search runs in the plugin agent, whose tool list holds only WebSearch, WebFetch and the evidence tools (no shell, no file writes). Its instructions treat page text as data and require it to report text addressed to it instead of acting on it. List outputs carry a note saying that quotes and publishers come from the web, and the package never interprets them. | `agents/share-research.md`, `interfaces/mcp_server.py` |
| Stored URLs and text in the panel and reports | Evidence URLs are stored and shown as data. The panel renders a link only for `https://` addresses, with `rel="noopener noreferrer"`, and fills all text with `textContent`; the HTML report escapes every value and applies the same https rule. | `interfaces/web/static/app.js`, `skills/_shared/mlb_report/share.py` |
| Local data | The data directory is created with `0700` permissions. The repository contains no data and no secrets (`.gitignore`). | `settings.py` |
| Dependency vulnerabilities | `pip-audit` runs in CI; Dependabot proposes weekly updates. | `.github/` |

Each of these mitigations is verified by tests under `tests/` (e.g. `test_injection_attempts_rejected`, `test_refuses_untrusted_host`, `test_key_only_in_header_never_in_url_or_bronze`, `test_rejects_non_loopback_host`, `test_api_requires_token_and_same_origin`).
